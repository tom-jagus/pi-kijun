# Pi Kijun

## Problem

Working with a coding agent requires repeated explanation of personal working
standards and project intent. Long progress narratives make it difficult to
recover current work, distinguish proposals from decisions, and review changes.

## Value

A personal, version-controlled workflow should reduce repeated explanation and
make daily work easier to discuss, resume, implement, and review. Project
records should remain readable and editable without an agent.

## Success

- A fresh session can identify the project's purpose, current work, and next
  useful action from concise records checked against the repository.
- The agent selects the relevant activity guidance, preserves its boundaries,
  and records conclusions rather than generating a project diary.
- Changes remain reviewable, with explicit editing and acceptance authority
  and no Git mutation merely because other work was completed.

## Boundaries

Use a small global contract, on-demand skills, and charter, brief, and slice
records. Source work remains manual-first unless explicitly authorized; writing
records does not imply acceptance. The operating contract and skills own the
procedures rather than this charter.

Link repository-owned resources without replacing machine-owned settings or
runtime data. Skills are behavioural guidance, not technical permission
controls. Allow independent content review through one read-only reviewer and
at most three reviewer invocations per request, with conclusions reported to the
user. Other orchestration, extensions unrelated to this review workflow, and
generated boards remain deferred until a demonstrated need justifies them.
Model choice remains with the user.
