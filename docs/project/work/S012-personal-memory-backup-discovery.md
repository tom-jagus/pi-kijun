# Recommend a personal memory backup approach

## Outcome

Help the user decide whether and how to back up private memory without exposing
it through the tracked Kijun repository.

## Acceptance criteria

- Compare no backup and a small set of suitable private backup options against
  loss, confidentiality, access, cost or effort, and recovery needs. Identify
  assumptions rather than claiming an existing backup is configured.
- Explain encryption and key recovery trade-offs where relevant, including
  risks of losing both the file and its recovery credentials.
- Explain how backup copies and Pi session history affect deletion and retention;
  a deleted active entry may remain elsewhere.
- Recommend a proportionate option and a practical restore approach, while
  leaving the choice to the user. Identify whether any further work is needed.
- Do not inspect private memory, configure services, copy personal data, or
  create backups without the user's separate authorization.

## Tasks

- [ ] Discuss the user's recovery needs and constraints without requesting
  sensitive memory content or credentials.
- [ ] Compare options and present a recommendation and restore procedure.
- [ ] Record the accepted decision or explicitly requested interim findings.
